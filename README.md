# Squad Finder

React + Vite web app, packaged for Android via Capacitor. `src/App.jsx` is
the existing Squad Finder app, unmodified — this project just gives it a
real build pipeline and a native Android shell.

## What's here

```
squad-finder-app/
├── package.json
├── vite.config.js
├── tailwind.config.js
├── postcss.config.js
├── index.html
├── capacitor.config.json      appId: com.squadfinder.app, appName: Squad Finder
├── .gitignore
└── src/
    ├── main.jsx
    ├── index.css
    └── App.jsx                 <- your existing app, unchanged
```

There is **no `android/` folder yet** — it's generated by the `cap add
android` command below, which needs to download Capacitor's native
Android template from npm. That step has to run on your machine; it
can't be produced without a live npm registry connection.

## Prerequisites (install once)

- Node.js 18+ and npm
- Android Studio (includes the Android SDK and a bundled JDK)
- A device or emulator to test on (Android Studio's Device Manager can create one)

## First-time setup

Run these from inside this project folder:

```bash
npm install
npx cap add android
npx cap sync android
```

`cap add android` creates the native `android/` project (Gradle files,
manifest, etc.) using the appId/appName from `capacitor.config.json`.
`cap sync android` copies the built web app into it and wires up any
Capacitor plugins — safe to re-run any time.

## Building the APK

```bash
npm run build          # builds the web app into dist/
npx cap sync android    # copies dist/ into the native project
npx cap open android    # opens the project in Android Studio
```

(Those three are also available as one command: `npm run android`.)

In Android Studio: **Build → Build Bundle(s) / APK(s) → Build APK(s)**.
The debug APK lands in `android/app/build/outputs/apk/debug/`. For a
release/signed APK, use **Build → Generate Signed Bundle / APK** instead,
which will walk you through creating a keystore the first time.

Prefer the command line? From inside `android/`:

```bash
./gradlew assembleDebug     # debug APK, no signing needed
./gradlew assembleRelease   # release APK, needs a signing config
```

## Building from a phone (no computer/Android Studio needed)

Android Studio itself can't run on a phone, but the build doesn't have
to happen on your device — `.github/workflows/build-apk.yml` in this
project builds the APK on GitHub's own servers instead:

1. Create a GitHub repo (the GitHub mobile app or github.com in your
   phone's browser both work) and push/upload this whole project to it.
2. Open the repo → **Actions** tab → **Build Android APK** → **Run workflow**.
3. Wait for the run to finish (a few minutes), then open it and download
   the `squad-finder-debug-apk` file under **Artifacts** — that's your
   APK, ready to install.

No local Node, JDK, or Android SDK needed — GitHub's runner installs
all of that itself for each run. Re-run the workflow any time you push
a change.

## Whenever you change the app

Every time `src/App.jsx` (or anything else in `src/`) changes:

```bash
npm run build
npx cap sync android
```

then re-build/run from Android Studio. `cap sync` is what pushes your
latest web build into the native shell — Android Studio won't pick up
web changes on its own.

## Useful checks

```bash
npx cap doctor     # reports Capacitor/Android version mismatches
```

## Known gaps to close before a real release

- **Authentication has no real backend yet.** Sign up / log in accept
  any valid-looking email + 6+ character password and just create a
  local session — nothing is checked against a real account system.
  `AuthProvider` (in `App.jsx`) is the one place to swap in Firebase
  Auth, Supabase Auth, or a custom API; the UI already calls
  `signUp` / `logIn` / `continueWithGoogle` / `requestPasswordReset`
  and expects a `{ email, profileComplete }` session back (or a
  thrown error, which the UI shows honestly instead of faking success).
- **Google sign-in and password reset are intentionally unimplemented
  integration points** — tapping them shows a clear "not connected
  yet" message rather than pretending to work. Wire them up once a
  real auth provider is connected.
- **Storage** now goes through a three-tier abstraction
  (`storageGet`/`storageSet`/`storageRemove` in `App.jsx`): Capacitor
  Preferences when running as the packaged Android app (this project's
  `package.json` already depends on `@capacitor/preferences` — just
  run `npx cap sync android` after install), `localStorage` in a plain
  browser, and an in-memory fallback otherwise. Login session and
  squad chat messages persist through this; passwords are never
  written to it.
- **App icon / splash screen** — this project uses Capacitor's Android
  defaults. Replace them with `@capacitor/assets` or manually in
  `android/app/src/main/res/` once you have real artwork.
- **Update manifest / APK URL** — `UPDATE_MANIFEST_URL` in `App.jsx` is
  still blank, and the in-app updater's Android download/install step
  is an intentionally unimplemented integration point. Both need a
  real host once you have one.
- **Signing** — the release build needs a keystore you generate and
  keep safe (Android Studio's "Generate Signed Bundle/APK" flow will
  create one on first use).
